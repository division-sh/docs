If pins and `connect` edges are new to you, read [Composing flows](/build/composition) first.

Every pattern in this section has a canonical, runnable bundle in the
[`examples/`](https://github.com/division-sh/swarm/tree/master/examples) directory of the
repository. The platform's own CI verifies every one of these against every change, so they
are never stale and always show the current idiom. Each ships with a README and
runs with the zero-config defaults:

```bash
git clone https://github.com/division-sh/swarm && cd swarm
swarm verify --contracts examples/routing/fan-in/barrier
swarm run start --contracts examples/routing/fan-in/barrier --event <trigger> --payload <file> --data ./data
```

Each example's README names the trigger event and ships a sample payload file.

## Routing and composition

| Example | What it proves |
|---|---|
| [`root-ingress`](https://github.com/division-sh/swarm/tree/master/examples/routing/root-ingress) | External events entering a root flow's input pin. |
| [`parent-connect`](https://github.com/division-sh/swarm/tree/master/examples/routing/parent-connect) | The `connect` block: parent↔child edges over declared pins. |
| [`template-select-or-create`](https://github.com/division-sh/swarm/tree/master/examples/routing/template-select-or-create) | Instances minted on first delivery by pin resolution. |
| [`template-select-existing`](https://github.com/division-sh/swarm/tree/master/examples/routing/template-select-existing) | `mode: select` — address an existing instance by carried identity. |
| [`template-create-minted-key`](https://github.com/division-sh/swarm/tree/master/examples/routing/template-create-minted-key) | `mode: create` with a platform-minted identity (`generated.uuid`). |
| [`template-reply`](https://github.com/division-sh/swarm/tree/master/examples/routing/template-reply) | Request/reply correlation declared on the receiving pin. |
| [`notify-all-children`](https://github.com/division-sh/swarm/tree/master/examples/routing/notify-all-children) | One parent event delivered across many child instances. |

## Fan-in and convergence

| Example | What it proves |
|---|---|
| [`fan-in/barrier`](https://github.com/division-sh/swarm/tree/master/examples/routing/fan-in/barrier) | The barrier join: members, window, dedup, timeout — deliver once when complete. |
| [`fan-in/stream`](https://github.com/division-sh/swarm/tree/master/examples/routing/fan-in/stream) | Stream aggregation: every deduplicated arrival delivered, completion still tracked. |

## Testing

| Example | What it proves |
|---|---|
| [`harness-injection`](https://github.com/division-sh/swarm/tree/master/examples/routing/harness-injection) | Injecting test events with `source: harness` pins — accepted during validation, never in production. |
