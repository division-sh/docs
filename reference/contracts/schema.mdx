`schema.yaml` declares a flow's public surface: its lifecycle, the pins other flows wire to,
and the agent roles it requires.

## State machine

<ParamField path="stages" type="map">
  The entity's lifecycle stages, each a map entry. Mark the entry stage `initial: true` and
  absorbing stages `terminal: true` (once an entity reaches one, new events for it are
  rejected and its timers are cancelled). A stage may also declare `timers:` that fire when an
  entity has sat in it too long. Omit `stages:` entirely for a stateless flow. The older
  `initial_state`/`states`/`terminal_states` list grammar still parses, but `stages:` is the
  canonical form and the only one stage timers attach to.
</ParamField>
<ParamField path="mode" type="string">
  `singleton` (default) or `template` — one instance per identity value.
</ParamField>
<ParamField path="instance" type="string">
  Template flows only: the scalar identity field (`instance: order_id` = one instance per
  order_id). Every selecting input pin must carry a field with this name; the pin's instance
  key derives from it. The older `instance: {by:}` block and `resolution.instance_key` are
  retired and rejected at load.
</ParamField>

## Pins

Pins are the flow's public interface. Event pins declare what it accepts and emits; data pins
declare which entity fields it reads and writes.

```yaml
pins:
  inputs:
    events: [order.created]
    reads: [priority]
  outputs:
    events: [order.fulfilled, order.cancelled]
    writes: [status, total]
```

No two flows may write the same data pin (a boot error). A pin-declared output event routes
through the parent package's `connect` edges; the receiving flow's input pin owns instance
selection via `resolution` and `carries`. The producer never targets recipients; see
[Events and routing](/concepts/events-and-routing).

## Required agents

<ParamField path="required_agents" type="list">
  The roles the flow needs. Each entry has `role`, `subscribes_to`, `emits`, and an optional
  `description`.
</ParamField>

Fulfillment is checked at boot on two conditions: an agent in `agents.yaml` whose map key
matches the `role`, and whose subscriptions and `emit_events` cover the declared
`subscribes_to` and `emits`.

## Other fields

<ParamField path="instance_variables" type="object">
  Variables populated at flow-instance creation via `config_from`, available to prompts as
  `{{variable}}`.
</ParamField>
<ParamField path="auto_emit_on_create" type="object">
  For template flows: an event the platform emits once a new instance is fully started.
</ParamField>

## Example

```yaml schema.yaml
initial_state: new
terminal_states: [fulfilled, cancelled]
states: [new, validated, fulfilling, fulfilled, cancelled]
pins:
  inputs:
    events: [order.created]
  outputs:
    events: [order.fulfilled, order.cancelled]
required_agents:
  - role: validator-agent
    subscribes_to: [order.created]
    emits: [order.validated]
```
