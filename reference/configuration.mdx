Swarm favors CLI flags; each flag has an environment-variable equivalent for deployment.
`swarm verify` is the only command that runs without a runtime or a token. Every other command
targets the runtime's API and needs a bearer token.

## Connecting to the runtime

The runtime exposes one HTTP listener serving health, readiness, `/v1/rpc`, `/v1/ws`, and the
MCP routes. Its default address is **`http://127.0.0.1:8081`**. The bundled Docker Compose
binds that same listener to **`:8070`** instead; aside from the port, the two are the same
surface.

CLI commands resolve connection settings in this order: flag, then environment, then config
file, then built-in default.

<ParamField path="--api-server <url>" type="string">
  Base URL of the runtime. Default `http://127.0.0.1:8081`. Env: `SWARM_API_SERVER`.
</ParamField>
<ParamField path="--api-token-file <path>" type="string">
  File holding the bearer token. Required for every command except `swarm verify`. Env:
  `SWARM_API_TOKEN` (the token value) or `SWARM_API_TOKEN_FILE`. An inline `--api-token` is
  not accepted, to keep secrets out of shell history.
</ParamField>

The optional CLI config file at `$XDG_CONFIG_HOME/swarm/config.yaml` accepts `api_server` and
`api_token_file`.

### swarm run

`swarm run` reaches a runtime in one of two ways:

- **Local (default).** With no `--connect`, it boots a runtime in process on
  `127.0.0.1:8081`. Override the port with `--api-port <n>`.
- **Connected.** With `--connect <url>`, it attaches the run to an already-running runtime
  (started by `swarm serve`) instead of booting its own.

Either way, a bearer token is required.

### Local startup flags

These flags configure a runtime that `swarm serve` or `swarm run` boots in-process. They have no
effect when attaching to a running runtime with `--connect`.

<ParamField path="--config <path>" type="string">
  Path to a Swarm runtime config (`config.yaml`). Resolution order: explicit `--config` first,
  then a `config.yaml` next to the running binary, then built-in defaults.
</ParamField>
<ParamField path="--data <path>" type="string">
  Path to the agent-visible read-only `/data` reference directory. Resolution order:
  `--data` > `workspace.data_source` in `config.yaml` > `SWARM_WORKSPACE_DATA_SOURCE` > the
  auto-default `.swarm/data/` (created next to `.swarm/dev.db` if it doesn't exist, so the runtime
  starts with no `/data` configuration). Available on both `swarm serve` and `swarm run`.
</ParamField>

`--store` and `--backend` are documented under [Runtime store](#runtime-store) and
[LLM backend and credentials](#llm-backend-and-credentials).

## Configuration files

Swarm uses two YAML files that share the name `config.yaml` but have different scopes, paths,
and schemas. They coexist; pick the one that matches what you are configuring.

| | CLI client config | Runtime config |
|---|---|---|
| **Audience** | every `swarm` command | `swarm serve` / `swarm run` at boot |
| **Path** | `$XDG_CONFIG_HOME/swarm/config.yaml` | `<binary-dir>/config.yaml`, or `--config <path>` |
| **Configures** | the CLI's API target, token, contract path | runtime startup: store, LLM, workspace, tuning |
| **Schema** | flat, six keys | nested, several sections |

### CLI client config

Optional. Place it at `$XDG_CONFIG_HOME/swarm/config.yaml` to set per-user CLI defaults. Six
keys are accepted; any other key is a parse error.

```yaml
api_server: http://127.0.0.1:8081
api_token_file: ~/.config/swarm/token
contracts_path: /absolute/path/to/contracts
platform_spec_path: /absolute/path/to/platform-spec.yaml
serve_api_listen_addr: 127.0.0.1:8081
serve_mcp_listen_addr: 127.0.0.1:8082
```

CLI flags override file values; the file overrides built-in defaults.

### Runtime config

Loaded by `swarm serve` and `swarm run` when they boot a local runtime. Resolution order:
explicit `--config <path>`, then `config.yaml` beside the running binary, then built-in
defaults. The full top-level shape:

```yaml
runtime:                      # event loop and recovery tuning
  max_concurrent_agents: 16
  event_poll_interval: 100ms
  recovery_on_startup: true

database:                     # Postgres connection (used when store.backend is postgres)
  host: 127.0.0.1
  port: 5432
  name: swarm
  user: postgres
  password: postgres
  sslmode: disable
  pool_size: 10

store:
  backend: sqlite             # sqlite (default) | postgres
  sqlite:
    path: .swarm/dev.db       # auto-created if missing

workspace:
  data_source: ./reference    # default: auto-created at .swarm/data/
  backend: ""                 # workspace-isolation backend (claude_cli uses Docker)

llm:
  backend: anthropic          # anthropic | claude_cli | openai_compatible (default anthropic)
  models:                     # alias -> { backend: concrete-model } overrides
    regular:
      anthropic: claude-3-5-sonnet
      claude_cli: sonnet
      openai_compatible: gpt-4o
  session:
    lock_ttl: 10s
    rotate_after_turns: 40
    rotate_on_parse_failures: 3
  claude_api:                 # tuning for the anthropic backend
    default_model: claude-3-5-sonnet
    haiku_model: claude-3-5-haiku
    max_retries: 3
    retry_backoff: 1s
  claude_cli:                 # tuning for the claude_cli backend
    command: claude
    timeout: 30m
    output_format: json
    retries: 2
    no_session_persistence: false
    use_tmux: false
  openai_compatible:
    base_url: https://api.example.com
    default_model: gpt-4o
    low_cost_model: gpt-4o-mini

extensions:                   # typed extensions; inline, namespaced per extension
  # ...
```

CLI flags override config keys (`--store > store.backend`, `--backend > llm.backend`,
`--data > workspace.data_source`), and the corresponding env vars override the file where both
are accepted. See the sections below for each subsystem's precedence.

<Warning>
  **`llm.runtime_mode` is retired** and rejected at boot; use `llm.backend`. The env-var
  equivalents `SWARM_LLM_RUNTIME_MODE` and `SWARM_LLM_BACKEND` are also rejected; backend
  selection is `--backend` or `llm.backend` only.
</Warning>

## Runtime store

The runtime stores events, entity state, gates, timers, and sessions in a relational database.
**SQLite is the default for local and development runs** (file-backed at `.swarm/dev.db`, no
service needed); Postgres is the opt-in backend for external and production deployments.

Select the backend with `--store sqlite` or `--store postgres`. `SWARM_STORE_BACKEND` and
`store.backend` in `config.yaml` also select it; the `--store` flag overrides both.

<ParamField path="SWARM_STORE_BACKEND" type="string">
  Runtime store backend: `sqlite` (local/dev default) or `postgres` (external/production opt-in).
  Config key `store.backend`; the `--store` flag overrides.
</ParamField>

<ParamField path="SWARM_DB_HOST / SWARM_DB_PORT / SWARM_DB_NAME / SWARM_DB_USER / SWARM_DB_PASSWORD / SWARM_DB_SSLMODE" type="string">
  Postgres connection parameters (used when `--store postgres` is selected). Defaults: `127.0.0.1`,
  `5432`, `swarm`, `postgres`, `postgres`, `disable`. Each `SWARM_DB_*` variable falls back to the
  standard libpq equivalent (`PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`) before the
  default.
</ParamField>

## LLM backend and credentials

Select the LLM backend with the `--backend` flag on `swarm serve` or `swarm run`, or with
`llm.backend` in `config.yaml`. **Environment variables never select the backend**: both
`SWARM_LLM_BACKEND` and the older `SWARM_LLM_RUNTIME_MODE` are retired and rejected at boot. The
default backend when nothing is set is `anthropic`. A flow with no agents boots without any
credential.

| Backend | Required credential | Notes |
|---|---|---|
| `anthropic` | `ANTHROPIC_API_KEY` | The Anthropic API transport. Credential is checked at the first agent turn. |
| `claude_cli` | `CLAUDE_CODE_OAUTH_TOKEN` | Drives the Claude CLI as a subprocess. Validated at boot when the bundle declares agents. Also needs the tool-gateway variables `SWARM_TOOL_GATEWAY_URL`, `SWARM_TOOL_GATEWAY_CONTAINER_URL`, `SWARM_TOOL_GATEWAY_TOKEN` (the repository `.env` provides them). |
| `openai_compatible` | `OPENAI_COMPATIBLE_API_KEY` | Any Chat Completions-compatible HTTP JSON endpoint. Also needs `llm.openai_compatible.base_url` (or `SWARM_OPENAI_COMPATIBLE_BASE_URL`) and `SWARM_OPENAI_COMPATIBLE_DEFAULT_MODEL`. `SWARM_OPENAI_COMPATIBLE_LOW_COST_MODEL` is optional, used when budget policy throttles an actor. |

The older profile ids `api` and `cli_test` remain as back-compat aliases for `anthropic` and
`claude_cli`. Credentials are read from the environment and a local credential store, and are
never logged or persisted.

## Budget caps

The `budget_*_percent` thresholds in `policy.yaml` are percentages of a monthly USD cap, set in
the `budget:` configuration section. A scope is monitored only when its cap is above zero. See
[Budget and cost](/operate/budget-and-cost).

```yaml
budget:
  global_monthly_cap: 500       # USD per month across the deployment
  per_entity_monthly_cap: 5     # USD per month per entity
  system_monthly_cap: 100       # USD per month for platform/system work
```

## Sharding

When a node fans a workload across multiple instances of an agent
([Agent sharding](/concepts/agents-and-sessions)), the `sharding:` section bounds the
parallelism so it cannot run away. The defaults apply when a key is omitted.

```yaml
sharding:
  max_shards_per_job: 8         # most shards a single job may split into
  max_concurrent_shards: 12     # most shards running at once across the runtime
  per_shard_timeout: 30m        # a shard that exceeds this is treated as failed
  per_shard_budget_cents: 0     # optional spend cap per shard (0 = none)
  max_retries_per_shard: 0      # retries before a shard is given up on
  circuit_breaker_threshold: 0  # shard failure rate that trips the breaker (0 = off)
```
